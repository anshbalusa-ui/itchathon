# On You — release acceptance checklist

This is an actionable distribution gate, not permission to publish. The offline MVP can be software-complete while physical validation and distribution approval remain outstanding. Exact current software receipts, source fingerprint and review branch are recorded in [final release readiness](ONYOU_FINAL_RELEASE_READINESS.md); do not substitute historical PR totals.

## Software and package gates

| Gate | Required observation / acceptance evidence |
|---|---|
| Reviewed integration | Confirm latest `main` and PR #27 ancestry, inspect newer teammate work and the focused readiness delta, retain PR #25/#26 implementation and every existing regression identity. Owner reviews the draft candidate; no automatic main merge or PR closure. |
| Complete fresh verification | Run `/usr/bin/python3 Scripts/verify_development.py --simulator UDID --output-root NEW_EXTERNAL_DIRECTORY` with Xcode/XcodeGen available. Require clean Debug build, all unit/UI cases, zero failures/skips/expected failures, generic unsigned iPhone SDK build, normal Release with testability disabled, selected Release checks and all bundle inspections. Match the final source fingerprint to the delivered candidate. |
| Actual native journey | Observe Body → saved avatar → Closet → supported saved shirt → Try on → visible garment → rotate/reset/hide/show/switch → close/reopen → return. Require actual geometry and rendered pixels, not titles alone. Manual measurement Save/Cancel/History must work without authorizing captured-avatar try-on. Retain actual simulator images and original failed diagnostic evidence outside Git. |
| Release isolation | Inspect Debug/iPhone/normal Release/Release-test app bundles. Normal Release must open native **On You**; internal `-fitcheck-*`, M1 and `-onyou-tryon-fixture` routes/resources must be excluded. The reviewed production human asset is intentionally retained with its pinned license/notice. |
| Required-reason manifest | Preserve no tracking and empty app-collected-data declarations where accurate; require SystemBootTime `35F9.1`, UserDefaults `CA92.1`, FileTimestamp `C617.1` and DiskSpace `E174.1`. DiskSpace covers the existing insufficient-storage check before capture writes. Passing a local manifest test is not App Store acceptance or an SDK-wide privacy certification. |
| Failure and ownership boundaries | Verify corrupt data, missing photo/avatar, unsupported pose/combination, cancellation, retake, rapid switching, background/foreground and stale async results. A failed try-on must offer recovery rather than a successful bare avatar. Preserve capture/admission thresholds and previous user data. |
| License/resource provenance | Retain reviewed MakeHuman CC0 and GarmentIQ MIT/model notices and asset provenance. Confirm packaged resources correspond to the reviewed source; owner reviews distribution rights and third-party disclosures. No downloaded decorative assets or fabricated retailer data. |

## Physical/device gates — NOT RUN in this readiness pass

| Gate | Required procedure / pass criterion |
|---|---|
| Compatible device/OS | On authorized test iPhones running supported iOS (project minimum **26.0**), check runtime Object Capture/Photogrammetry support for body capture and world-tracking/scene-depth support for metric shirt capture. Do not promise support from the model name or SDK compilation alone. Exercise unsupported-device recovery. |
| Camera permission and interruption | In the isolated validation sandbox, exercise first request, allow, deny/restrict, explicit Settings recovery, cancellation before a permission callback, interruption, backgrounding and reopening. No capture before deliberate entry/permission; no stale callback revives a canceled attempt. No global privacy reset or erasure of an existing app. |
| Body and shirt capture | Complete every case in [device validation](ONYOU_DEVICE_VALIDATION.md), retaining failures/retries and approved nonpersonal reference observations. Require two completed body passes, at least 60 distinct accepted aligned images and existing depth admission. Measure real device capture/reconstruction latency; simulator rejection timing is not reconstruction performance. |
| Storage under lock / backup | Check protection classes on active model/manifest, garment photo/manifest and transient photos/checkpoints; test locked/unlocked behavior and actual backup/restore exclusion of scan/Closet directories. Simulator attributes or source declarations do not prove on-device encryption/backup behavior. |
| Manual measurements/history policy | Review actual UserDefaults protection, platform backup/transfer behavior, retention and deletion expectations separately. The current `on-you.measurements.v1` store has no established explicit scan/photo protection or backup-exclusion guarantee. Approve the policy and any resulting requirement before a migration; do not silently alter existing data. |
| Deletion and I/O failures | Verify ordinary targeted deletion and unrelated-data retention; inject authorized sandbox save/replacement/unlink failures and abrupt termination. Avatar partial deletion reports an error; Closet manifest-first deletion can leave an orphaned image if unlink fails, and replacement cleanup is best effort. These are source-identified failure boundaries, not reproduced device defects. Record/report the actual outcome; approve any necessary specific repair before claiming complete erasure/recovery guarantees. |
| Accessibility and displays | Retain current small/large portrait and actual light/dark/maximum-text simulator proof. On supported phones check VoiceOver focus/order/values, touch targets, contrast, all advertised orientations, motion settings, keyboard/scroll behavior and scan guidance over the real camera. Titles may use native navigation truncation; content/actions must remain readable and reachable by scrolling. |
| Stability and performance | Exercise repeated capture, reconstruction, save/load, try-on and lifecycle cycles under realistic memory/thermal/storage conditions. Record cold versus warm preparation, peak/retained memory, hangs/crashes and dropped-frame observations. Simulator offscreen snapshots are not phone FPS; a process-lifetime peak is not a retained-memory/leak measurement. |
| Physical claims | Follow the [fit roadmap](ONYOU_FIT_VALIDATION_ROADMAP.md) with approved independent references, uncertainty/error budgets and repeatability. Until passed, claim only illustrative rendering and captured visible outer surfaces—not accurate hidden anatomy, fabric stretch, pressure, drape or recommended size. |

## Distribution and owner approval — NOT RUN / NOT APPROVED

- Produce and inspect an authorized signed device build/archive using existing approved profiles, a deliberate final bundle identity/version and the reviewed Release configuration. Project `CODE_SIGN_IDENTITY=-` is ad-hoc signing; local verification explicitly uses `CODE_SIGNING_ALLOWED=NO`. Neither establishes a distribution identity, provisioning profile, installable phone build or App Store archive acceptance.
- Review privacy policy/App Store privacy labels, permission text, collected-data/SDK inventory, diagnostics, platform backup behavior, retention/deletion, export declarations and required legal/support information against actual behavior. Static absence of native upload calls does not establish all OS/SDK network behavior. Explicit external **View product** / license links are user actions, not an app-managed upload or shopping service.
- Review age/content ratings, accessibility disclosures, supported devices/orientations, store screenshots/metadata, icon/versioning, signing, owner access and distribution channel. Use actual reviewed screenshots; never describe synthetic fixtures as real scans.
- Keep accounts, backend, feeds, synchronization, app-managed cloud backup, payments and additional garment categories outside this offline release unless separately approved. Dependencies are in the [post-MVP roadmap](ONYOU_POST_MVP_ROADMAP.md).
- Owner approval is required before merging to main, closing earlier PRs, changing production credentials, uploading or publishing. This assignment performs none of those actions.

Primary required-reason references: [Apple required-reason API policy](https://developer.apple.com/documentation/bundleresources/describing-use-of-required-reason-api) and [TN3183](https://developer.apple.com/documentation/technotes/tn3183-adding-required-reason-api-entries-to-your-privacy-manifest).
